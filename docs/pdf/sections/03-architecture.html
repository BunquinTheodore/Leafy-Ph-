System architecture

Leafy has one front door. The browser only talks to Next.js, Next.js talks to FastAPI, and FastAPI is the only thing that touches the database, storage, the ML service and Google's public certificates. The only direct browser call to Google is the sign in popup.

Four tiers

Client

Browser

Shows the Leafy UI. It holds two httpOnly cookies, leafy_at and leafy_rt, and never sees a token in JavaScript. It never calls FastAPI, so there is no browser CORS.

Web tier

Next.js 15

Middleware refreshes the session and guards routes. Server components fetch data with apiFetch. Route handlers proxy changing calls to FastAPI and set cookies.

API tier

FastAPI

REST under /api/v1 in four layers: router, controller, service, repository. It owns business rules, transactions and the error envelope. Only Next.js can reach it.

Services

Data and outside systems

PostgreSQL 16 for data, an S3 compatible store for images, the ML service for predictions and Firebase Auth with Google for sign in. Only FastAPI calls them, except presigned image links.

Status

Every box here is built. The ML service box runs the stub, or a dev only fake, until the teammate’s model arrives. The Dockerfiles are not written yet, so development uses native services.

Firebase console steps

Authentication, Sign-in method: enable Google and set the support email. Authentication, Settings, Authorized domains: keep localhost and add the production domain. Google Cloud Console, Credentials: restrict the Browser API key by HTTP referrer. Copy the web config values into app/.env.local and the project id into api/.env. The README has the full steps.

Why the browser never calls FastAPI

Tokens stay out of JavaScript, there is no CORS to configure, and FastAPI can stay unpublished in production. It trusts X-Forwarded-For only from the compose network.
