UI behavior

How Leafy moves and responds: panels, cursor, sound, splash, progress and layout. A PDF cannot animate, so each motion is shown as numbered frames, read left to right and top to bottom.

Sideways panels

Every page is a single screen stage. Long content is split into horizontal panels (SlidePanels) instead of a long vertical scroll. The base is CSS scroll snap, with framer motion or GSAP on top, so it still works if scripts are late.

Cursor reactions

Everything the cursor touches responds in one calm way. One passive pointer listener, throttled with requestAnimationFrame, writes CSS variables, so components never re-render per mouse move.

VariableScopeMeaning
--mx, --myViewport, set oncePointer position on the screen.
--px, --pyPer hovered elementPointer position inside the element, 0 to 1.
Built

The pointer components live in app/src/components/interaction/: PointerProvider, Magnetic, TiltCard, ParallaxImage, SpotlightSurface, VeinLink and Tooltip. Unit tests cover the math: clamping, damping and reduced motion.

Hover interactions

ElementWhat happens
ButtonsMagnetic pull of a few pixels toward the cursor, a soft green glow that follows the pointer, a gentle press in, and a ripple or leaf burst on activation. The cursor switches to the pointer variant.
CardsPlants, diseases, scans and stats. Tilt of at most about 6 degrees with a light glare that tracks the cursor, a lifted glow, a brighter border and an Open hint.
ImagesSlow zoom to about 1.04 times and a parallax shift against the cursor, a spotlight vignette, and a caption slide in. Disease reference images get a magnifier lens on desktop.
TextLinks draw a vein shaped underline from the cursor side. Josefin headings get a soft glow and slight letter spacing ease by transform only, so one line titles stay one line. Body paragraphs stay still. Inline terms show a definition tooltip on hover and focus.
SurfacesA soft radial spotlight follows the cursor over glass panels and the forest background. Vein line dividers light up near the pointer.
3D scenesHero, auth and handbook leaves lean and sway toward the cursor with a damped spring. The scan beam can be steered on the preview. The result leaf orbits on drag. Hotspots pulse and show labels.
NavigationA sliding pill follows the hovered nav item. Panel dots grow and preview the target title. Panels rubber band on drag.

Sound effects map

Soft, organic UI sounds synthesized with the Web Audio API: oscillators and filtered noise envelopes. There are no audio files and no extra requests. UI sounds stay under 250 ms and scan sounds under 600 ms. Lengths and minimum gaps below are the built values in app/src/components/sfx/.

Brand fit

A small sound palette (pitch family, envelopes, volume levels) is documented in the /brand guide so the sounds feel like one product with the visuals and the cursor.

How a sound is chosen

One delegated pointerdown and pointerover listener on the document maps the element to a sound. Components override with data-sfx="click|toggle|success|error|none" or call sfx.play('success'). Disabled elements and data-sfx="none" stay silent. The diagram after the rules shows the whole path.

Splash screen

A full screen LEAFY screen shown on every full page load: first open and every browser refresh. It does not show on in app client navigation. The name comes from one BRAND_NAME constant.

TopicRule
TimingMinimum about 0.9 s, hard maximum about 2.2 s. A tiny inline script removes it when fonts are loaded and the first route is hydrated. A pure CSS fallback animation hides it if JavaScript fails. In the built checkpoint run it began leaving at 985 ms.
MotionLetters fade and slide in, a leaf draws beside the wordmark, the overlay lifts (translate and opacity, GPU only).
Accessibilityaria-hidden with role="status" text for screen readers: Loading Leafy. It traps no focus.
PerformanceNo extra requests: inline CSS, the already loaded font with font-display: swap and preload. position: fixed, so no layout shift. The real LCP element is painted underneath.
Skipped forCrawlers and Lighthouse (navigator.webdriver or ?nosplash), so scores measure the real page.

Progress UI for the scan

The user always sees where things stand. Upload is a real percentage. The server stages come from the status and stage the API reports. The analyzing stage has no true percentage, so its bar eases toward 90% and reaches 100% only when the result arrives.

Layout rules: fill the screen

3D scenes

All 3D code is client only and lazy loaded per route. Content is real HTML on top, and canvases are aria-hidden. The shared module lives in app/src/components/three/ and is built, with the scan beam and the orbit view of the result in three/scan/.
