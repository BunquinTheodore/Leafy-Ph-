System architecture

Leafy has one front door. The browser only talks to Next.js, Next.js talks to FastAPI, and FastAPI is the only thing that touches the database, storage, email, the ML service and Google.

Four tiers

Client

Browser

Shows the Leafy UI. It holds two httpOnly cookies, leafy_at and leafy_rt, and never sees a token in JavaScript. It never calls FastAPI, so there is no browser CORS.

Web tier

Next.js 15

Middleware refreshes the session and guards routes. Server components fetch data with apiFetch. Route handlers proxy changing calls to FastAPI and set cookies.

API tier

FastAPI

REST under /api/v1 in four layers: router, controller, service, repository. It owns business rules, transactions and the error envelope. Only Next.js can reach it.

Services

Data and outside systems

PostgreSQL 16 for data, an S3 compatible store for images, SMTP for email, the ML service for predictions and Google for sign in. Only FastAPI calls them, except presigned image links.

Google Cloud Console steps

The README section on this is still a stub. The steps are: create an OAuth consent screen, then a Web client with the redirect URIs above, and copy the id and secret into .env with GOOGLE_MOCK=0. Until then the mock provider is used.

Why the browser never calls FastAPI

Tokens stay out of JavaScript, there is no CORS to configure, and FastAPI can stay unpublished in production. It trusts X-Forwarded-For only from the compose network.
