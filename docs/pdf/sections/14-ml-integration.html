ML integration

For whoever writes the leaf classifier. The API ships the contract, a stub and a fake. The real predict() is yours, and it is the only piece the app still needs.

The contract

Subclass MLInferenceService (api/app/services/ml/base.py) and implement one method.

from app.services.ml.base import MLInferenceService class MyModel(MLInferenceService): def predict(self, image: bytes) -> dict[str, str]: ... return {"plant": "tomato", "disease": "early-blight", "confidence": "0.93"}
PartRule
imageA sanitized JPEG made by the API: long edge at most 2048 px, EXIF and GPS removed.
Return valueA dict[str, str] with string keys and string values only.
plantA plant slug from the table below, or unknown.
diseaseA disease slug of that plant, or healthy, or unknown.
confidenceOptional. A decimal string from "0" to "1", such as "0.93".
Threads and timeThe call blocks. The API runs it in a worker thread with a timeout, so it must be safe to call from several threads. Load the model once in __init__.
FailureRaise any exception. The scan is stored as failed (prediction_failed) and the message is never shown. NotImplementedError maps to ml_unavailable (503).

Wrong or unknown slugs never crash a scan: the API resolves them to an unknown verdict. They do hurt accuracy, so stay inside the table.

Valid slugs

The source of truth is api/app/seeds/labels.json. Load that file instead of hard coding the list. Blueberry and Soybean have no diseases, so for them return healthy or unknown. Raspberry is not in the catalog: answer unknown.

Names that differ from the original DAHON prompt: Corn (maize) is corn, Cherry (including sour) is cherry, Bell Pepper is bell-pepper, Haunglongbing (Citrus greening) is orange and huanglongbing, Esca (Black Measles) is grape and esca. Common alternative spellings are tolerated through api/app/seeds/slug_overrides.yaml, but return the canonical slug.

Plugging it in

Install your package into the API environment and set one variable. The factory (api/app/services/ml/factory.py) imports the module, requires the class to subclass MLInferenceService, and calls it with no arguments, so read weight paths from environment variables inside __init__.

ML_SERVICE=my_package.my_module:MyModel
ML_SERVICE valueBehavior
stub (default)Raises NotImplementedError on every scan, so the API answers 503 ml_unavailable.
dev-fakeDev only. Picks a label from the image hash so the UI can be exercised. Refuses to start when ENV=prod.
package.module:ClassYour model. A bad spec fails fast at startup with MLConfigurationError.

Testing your class

Check it against the contract without running the API.

labels = json.loads(Path("api/app/seeds/labels.json").read_text()) result = MyModel().predict(Path("some_leaf.jpg").read_bytes()) assert set(result) <= {"plant", "disease", "confidence"} assert all(isinstance(v, str) for v in result.values()) assert result["plant"] in labels["plants"] or result["plant"] == "unknown" allowed = {*labels["plants"].get(result["plant"], []), "healthy", "unknown"} assert result["disease"] in allowed

To exercise the whole API flow with no model, use FakeMLService in api/tests/unit/test_ml_service.py. It returns tomato, healthy, 0.93 for any image. Run uv run pytest in api/ to confirm nothing else broke.

Where feedback goes

Corrections from members

Members can mark a result as wrong and say what it really was. Export those corrections as CSV with python -m app.tools.export_feedback (scan id, predicted and corrected labels, image key) to see where the model is weak. Scan images are not used for training unless the team decides so and updates the Privacy Policy.
