REST API

All endpoints live under /api/v1. The browser never calls them directly: Next.js route handlers and server components proxy every call.

Conventions

Envelope

One response shape

{success, data, error:{code, message, details, request_id}}. Messages are static text, never the raw exception.

Tracing

Request id

Every response carries X-Request-Id. The same id appears in the error body and in the structured JSON logs.

Auth

Bearer access token

Protected calls send the 15 minute access token. Next.js attaches it from the httpOnly cookie.

Ownership

404, never 403

Another user's scan answers 404. Every scan query is scoped by user_id.

Next.js route handlers

These are the only URLs the browser calls. State changing handlers run assertSameOrigin first. Uploads stream through with a body of at most 8 MiB.

HandlerPurpose
/api/auth/register/api/auth/login/api/auth/logout/api/auth/refresh
Call FastAPI, then set or clear the leafy_at and leafy_rt cookies.
/api/auth/google
POST. Same origin check, then hand the Firebase ID token to FastAPI and set the session cookies.
/api/me/api/me/password
Profile, password and account delete. Account delete clears the cookies.
/api/scans/api/scans/[id]
Create, poll, list, retry, delete and feedback for scans.

Error codes

Every error uses the envelope. The status is the HTTP status. Codes marked Next only never come from FastAPI. The first table covers sign in, tokens, account and upload errors. The second covers server and scan state errors.

CodeHTTPMeaning
not_authenticated401No valid access token on a protected call.
token_expired401Access token expired. Next.js refreshes and retries once.
invalid_token401Access token is malformed or fails verification.
invalid_credentials401Wrong email or password. Same message for both, and for Google only accounts.
refresh_invalid401Refresh token unknown, expired or revoked.
refresh_reuse_detected401A rotated token was replayed after the 10 s grace window. The whole family is revoked.
password_incorrect403Current password is wrong or missing on change (when no recent Google session applies) or on delete.
csrf_failed (Next only)403Origin check failed on a state changing handler.
email_taken409Registering with an email that already has an account.
google_auth_failed400Generic Google failure, or Google sign in is disabled (empty FIREBASE_PROJECT_ID). Details are logged.
google_email_unverified400The Firebase token has no verified email.
not_found404Missing resource, or a scan owned by someone else.
payload_too_large413Body over the 8 MiB cap.
unsupported_media_type415Upload is not JPEG, PNG or WebP.
validation_error422Request fields fail validation.
invalid_image422Image fails decode, pixel cap of 40M, or sniff checks.
invalid_cursor400Keyset cursor is not valid.
rate_limited429Too many attempts. Sends Retry-After.
CodeHTTPMeaning
internal_error500Unexpected failure. Details are logged, not returned.
prediction_failed502Prediction errored or timed out. Stored as the scan failure_code.
ml_unavailable503The stub raised NotImplementedError. Shown as "Analysis isn't available right now".
storage_unavailable503S3 could not store the image.
scan_not_failed409Retry on a scan that has not failed.
scan_not_completed409Feedback sent before the scan completed.
scan_quota_exceeded409Stored scan cap reached. The UI asks to delete old scans.

Additions in the built API, not in the original plan: service_unavailable (503), method_not_allowed (405) and reauth_required (403, a Google only user needs a fresh sign in before deleting). The 502 for prediction_failed and 409 for scan_quota_exceeded are also build decisions; the plan lists the codes without statuses.

How limits behave

Limits use slowapi in memory for v1, so they reset when the API restarts. Redis is the upgrade path. A limited call answers 429 rate_limited with Retry-After, and the UI shows a countdown.
