Security and verification

What protects accounts and uploads, the speed targets the site must meet, how the work is proven, and what is still open.

Security checklist

AreaControl
CookieshttpOnly, Secure in production with the __Host- prefix, SameSite=Lax, Path /. leafy_at lasts 900 s, leafy_rt 30 days.
Request originOrigin check (assertSameOrigin) on every state changing Next handler. sanitizeNext accepts only paths that start with / and not //.
Network exposureFastAPI is not published in production. It trusts X-Forwarded-For only from the compose network.
Passwordsargon2id, with a dummy hash check on unknown email. Length 10 to 128, not the email, not common. With no email, a new password without the current one is accepted only after a Google sign in under 10 minutes old.
Tokens and errorsRefresh tokens are stored hashed (sha256). Rotation with reuse detection revokes the whole family. One message for wrong credentials. There is no email channel, so nothing to enumerate or intercept.
Uploads8 MiB cap at Next, in ASGI middleware and in the streaming read. Magic byte sniff, Pillow decode, 40M pixel cap, EXIF and GPS stripped by re-encoding, server generated keys. The model receives the sanitized JPEG (long edge at most 2048 px).
Rate limitsPer ip, email and user limits (slowapi in memory for v1).
StoragePresigned URLs signed against S3_PUBLIC_ENDPOINT. Private scan bucket links last 10 minutes.
Browser headersCSP with nonce, HSTS, frame-ancestors 'none', nosniff.
Google sign inFirebase ID token checked server side with no Admin SDK: RS256 signature via cached securetoken certificates, iss, aud, exp, iat, auth_time, provider and email_verified. No secret anywhere. Mock mode refused in prod. CSP opened only for the popup hosts.
Data accessEvery scan query is scoped by user_id. Another user's scan answers 404.
Logging and supply chainNo secrets or tokens in logs, static error messages, an audit log line for Google link and create events. pip-audit, pnpm audit and a gitleaks scan in CI. No third party analytics or trackers.

How we get there

AreaApproach
RenderingServer components and ISR for the public handbook and landing. Route level code splitting. No heavy libraries on public pages (tree shaken drei imports, framer-motion LazyMotion).
Fontsnext/font self hosted and preloaded: 3 families, limited weights, display: swap, adjustFontFallback.
Imagesnext/image for static imagery (AVIF and WebP, sized, priority only on the LCP image). Catalog images pre-resized at seed time.
3DThree.js loads after idle by dynamic import, with a static poster as the LCP candidate. One canvas per page, frameloop="demand", DPR cap. Models are Draco or meshopt compressed under 300 KB.
Caching and networkBrotli or gzip. Cache-Control immutable for hashed assets and 3D models. preconnect to the S3 public host.
Layout stabilityExplicit sizes, reserved panel heights, and content-visibility: auto for offscreen panels.
Third party scriptsNone.

Verification plan

CheckPass condition
Documentation PDFPasses the overlap and clipping checks and the page by page visual review. Bookmarks, links and embedded fonts work. Matches the plan section by section.
Compose stackdocker compose up: postgres and minio healthy. Migrations and python -m app.seeds --check pass (13 plants, 27 diseases).
API testspytest green with 80 percent or more coverage, including ownership (user B gets 404), refresh rotation and reuse, and account deletion while S3 is down.
ML contractWith a fake ML service, POST /scans stores the image in MinIO and returns disease details. The stub returns 503.
Browser flowRegister, upload, result panels, history, delete, logout, plus the recovery journey (Google sign in, then a new password without the current one). A signed out /dashboard redirects to /login.
E2E, layout and speedPlaywright passes at 360, 768 and 1440 widths. The splash shows on a hard refresh, hides within 2.2 s, and skips client navigation and Lighthouse runs. Lighthouse CI and PageSpeed Insights meet the thresholds (both wait for hosting).
Google and recovery testsFake Google (GOOGLE_MOCK=1): new user, link, unverified email, wrong aud, iss or provider, bad signature, unknown kid, expired, disabled, set password, delete. Recovery: fresh Google session resets, stale one cannot, password session needs the current password.

Glossary

TermMeaning
Access tokenShort lived (15 min) JWT sent as a bearer token to the API.
Refresh tokenOpaque token, valid 30 days, replaced on every use.
Reuse detectionReplaying a rotated refresh token revokes the whole family.
Firebase ID tokenA signed JWT from Firebase Auth that proves who signed in with Google. FastAPI verifies the signature with Google's public certificates.
Authorized domainsSites in Firebase Auth settings that may open the Google popup.
EnvelopeThe fixed JSON shape {success, data, error} of every API response.
SlugA lowercase URL name for a plant or disease, such as early-blight.
Recent Google sessionA Google sign in under 10 minutes old. It may set a new password without the current one.
VerdictThe scan outcome: disease, healthy or unknown.
StageThe step of a processing scan: validating, analyzing or saving.
Keyset cursorPaging by the last seen (created_at, id), not an offset.
Presigned URLA temporary signed link that lets the browser read one stored image directly.
OutboxThe storage_deletion table of image keys to delete later.
ISRIncremental static regeneration: pages rebuilt on a timer.
Wave and gateA wave is parallel work. A gate is the checks before the next wave.
LCP, INP, CLSWeb vitals for load speed, responsiveness and layout stability.
DAHONThe original prototype. The word means leaf in Filipino. It is credited as the origin, not used as the brand.
