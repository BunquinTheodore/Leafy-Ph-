# ML integration guide

This is the one page for whoever writes Leafy's leaf classifier. The API ships the contract, a stub and a
fake for tests. The real `predict()` is yours.

## 1. The contract

Subclass `MLInferenceService` (`api/app/services/ml/base.py`) and implement one method:

```python
from app.services.ml.base import MLInferenceService


class MyModel(MLInferenceService):
    def predict(self, image: bytes) -> dict[str, str]:
        ...
        return {"plant": "tomato", "disease": "early-blight", "confidence": "0.93"}
```

- `image` is a sanitized JPEG made by the API: long edge at most 2048 px, EXIF and GPS removed.
- Return a `dict[str, str]` (string keys and string values only):
  - `"plant"`: a plant slug from the table below, or `"unknown"`.
  - `"disease"`: a disease slug **of that plant**, or `"healthy"`, or `"unknown"`.
  - `"confidence"` (optional): a decimal string from `"0"` to `"1"`, for example `"0.93"`.
- The call blocks. The API runs it in a worker thread with a timeout, so it may use CPU or GPU, but it must be
  safe to call from several threads. Load the model once in `__init__`.
- On failure raise any exception. The scan is stored as failed (`prediction_failed`) and the message is never
  shown to users. `NotImplementedError` (what the stub raises) maps to `ml_unavailable` (HTTP 503).
- Wrong or unknown slugs never crash a scan: the API resolves them to an `unknown` verdict. They do hurt
  accuracy, so stay inside the table.

## 2. Valid slugs

The source of truth is `api/app/seeds/labels.json` (generated by `api/tools/extract_dahon.py`). Do not hard code
the list; load that file. Shape:

```json
{
  "version": 1,
  "reserved": {"healthy": "healthy", "unknown": "unknown"},
  "plants": {"tomato": ["bacterial-spot", "early-blight", "..."], "blueberry": []}
}
```

| Plant slug | Disease slugs |
|---|---|
| apple | apple-scab, black-rot, cedar-apple-rust |
| bell-pepper | bacterial-spot, phytophthora-blight |
| blueberry | none |
| cherry | powdery-mildew |
| corn | common-rust, gray-leaf-spot, northern-corn-leaf-blight |
| grape | black-rot, esca, leaf-blight |
| orange | huanglongbing |
| peach | bacterial-spot |
| potato | early-blight, late-blight |
| soybean | none |
| squash | powdery-mildew |
| strawberry | leaf-scorch |
| tomato | bacterial-spot, early-blight, late-blight, leaf-mold, septoria-leaf-spot, spider-mites, target-spot, tomato-mosaic-virus, tomato-yellow-leaf-curl-virus |

Reserved values: `healthy` (the plant is recognised and the leaf looks fine) and `unknown` (not recognised, or
the photo is unusable). Blueberry and Soybean are in the catalog with zero diseases, so for them return
`healthy` or `unknown`. Raspberry is not in the catalog: answer `unknown` for it.

Names that differ from the original DAHON prompt (`DAHON-main/.../ML/ML.py`): "Corn (maize)" is `corn`, "Cherry
(including sour)" is `cherry`, "Bell Pepper" is `bell-pepper`, "Haunglongbing (Citrus greening)" is
`orange` / `huanglongbing`, "Esca (Black Measles)" is `grape` / `esca`. Common alternative spellings are
tolerated through the aliases in `api/app/seeds/slug_overrides.yaml`, but return the canonical slug.

## 3. Plugging your class in

Put your package on the API's Python path (install it into the API environment) and set:

```
ML_SERVICE=my_package.my_module:MyModel
```

The default is `ML_SERVICE=stub`, which raises `NotImplementedError` on every scan. The factory
(`api/app/services/ml/factory.py`) imports `my_package.my_module`, requires `MyModel` to subclass
`MLInferenceService`, and calls `MyModel()` with no arguments, so read weights paths from environment variables
inside `__init__`. A bad spec fails fast at startup with `MLConfigurationError`.

## 4. Testing

Check your class against the contract without running the API:

```python
import json
from pathlib import Path

from my_package.my_module import MyModel

labels = json.loads(Path("api/app/seeds/labels.json").read_text())
result = MyModel().predict(Path("some_leaf.jpg").read_bytes())

assert set(result) <= {"plant", "disease", "confidence"}
assert all(isinstance(v, str) for v in result.values())
assert result["plant"] in labels["plants"] or result["plant"] == "unknown"
allowed = {*labels["plants"].get(result["plant"], []), "healthy", "unknown"}
assert result["disease"] in allowed
```

To exercise the whole API flow with no model at all, use the fake service
(`FakeMLService` in `api/tests/unit/test_ml_service.py`). It returns
`{"plant": "tomato", "disease": "healthy", "confidence": "0.93"}` for any image, and the factory test loads it with the
spec `tests.unit.test_ml_service:FakeMLService`. Run `uv run pytest` in `api/` to confirm nothing else broke.

## 5. Where scan feedback goes

Users can mark a result as wrong and say what it really was. A CSV export of those corrections
(`python -m app.tools.export_feedback`, planned with the scan feedback screens) will show where the model is weak. Scan images are not used for training
unless the team decides so and updates the Privacy Policy.
